# Storage layout

This repository has **two** storage roots with different owners and lifetimes.
Putting a file in the wrong one is the easy mistake here, so this file exists to
make the split explicit.

## `storage/` — application data

Owned by the application. This is where durable artefacts that belong to users
or to the product live.

| Path | Contents | Lifetime |
|---|---|---|
| `storage/social_uploads/YYYY/MM/` | Team message attachments. Mirrors the `social_attachments` table. | Durable |
| `storage/user_files/YYYY/MM/` | Workspace file library. Mirrors the `user_files` table. Served only through `api/workspace.php` after an ownership check. | Durable |
| `storage/model_training/latest_dataset.jsonl` | Current full training corpus export. | Regenerated hourly |
| `storage/model_training/latest_incremental.jsonl` | Current incremental export. | Regenerated hourly |
| `storage/model_training/runtime_feedback.jsonl` | Runtime feedback rows fed into training. | Append-only |
| `storage/model_training/artifacts/` | LoRA adapter output and the generated `Modelfile.*`. | Regenerated hourly |
| `storage/model_training/snapshots/` | Hourly point-in-time copies of the corpus. | **Pruned** (see below) |
| `storage/hf_datasets/` | Imported Hugging Face datasets. | Durable |
| `storage/cache/` | Search and response caches. | Disposable |
| `storage/ai_os/`, `storage/logs/`, `storage/render_jobs/` | Runtime scratch. | Disposable |

`storage/security/`, `storage/agent_state/` and `storage/projects/` are **stale
copies** left over from before the runtime state moved under `api/lib/`. Nothing
writes them; their newest contents date from 2026-09-09 while the live
counterparts are current. `api/lyra_admin_data.php` still lists the old paths as
a fallback, which is why they were kept. They are a few KB and can be ignored, or
deleted once that fallback is removed.

## `api/lib/storage/` — agent and runtime state

Owned by the orchestration layer. `chat_storage_dir($sub)` in
`api/lib/chat/execution_foundation.php` resolves relative to **this** root, not to
the top-level `storage/`.

| Path | Contents |
|---|---|
| `api/lib/storage/security/audit/chat_audit.jsonl` | The orchestration audit log. Read by `pages/dev-stats.php`. |
| `api/lib/storage/security/audit/.lyra_ad_*.json` | Cached admin-dashboard metrics. |
| `api/lib/storage/agent_state/` | Per-agent runtime state. |
| `api/lib/storage/projects/state/` | Per-project agent state. Note this is unrelated to the `projects` **table** in `storage/`'s sibling workspace feature. |
| `api/lib/storage/intelligence_state/` | Conversation intelligence state. |
| `api/lib/storage/cache/` | Runtime caches. |

### `chat_audit.jsonl` grows without bound

It is append-only and was ~62 MB at the time of writing. `pages/dev-stats.php`
reads only the last 1,500 lines of it, so trimming older lines is safe in
principle, but nothing does so yet. Worth a rotation policy before it becomes a
problem.

## Snapshot retention

`storage/model_training/snapshots/` is written by
`cron/continuous_model_learning.php` on every run. That script also prunes it,
honouring:

```
LYRALINK_SNAPSHOT_RETENTION_HOURS=24     # default 72 if unset
```

These snapshots are traceability artefacts. **No code reads them back** — the
training run consumes `latest_dataset.jsonl` and `latest_incremental.jsonl`, and
the authoritative data is the `dataset` table in MySQL, so any snapshot can be
regenerated by re-running the export.

At the 72-hour default the directory settled at 214 files / 3.33 GB, which is
what the retention window costs rather than a leak. It is set to 24 hours here,
which keeps a full day of history for about a third of the space.

## Web access

`storage/` is not served. `.htaccess` blocks dotfiles and the extensions
`.py .pyc .sh .jsonl .md .safetensors .pt .ckpt .toml .yml`, plus `.env`,
`composer.*`, `.git*`, `*.ini|log|sql|sqlite|bak|old|dist`, and denies `vendor/`
and `scripts/`. Verified live: `/storage/...` and
`/api/lib/storage/security/audit/chat_audit.jsonl` both return 403.

Requesting a library PHP file directly (for example `/api/lib/finance.php`)
returns 200 with an **empty body**: the file executes and produces no output, so
no source is disclosed. The 200 is cosmetic rather than a leak.

## `.gitignore`

Runtime caches, model-training artefacts, virtualenvs, `node_modules/` and
`dist/` are ignored. The published desktop installers under `desktop-updates/`
ARE tracked, because that is the download surface the site serves.
